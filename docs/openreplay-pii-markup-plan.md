## 1. Задача одной строкой

Трекер маскирует **цифры** (`obscureTextNumbers`) и значения полей ввода (`defaultInputMode: 2`).
**Буквы не маскирует ничто:** ФИО, адреса и свободные комментарии операторов попадают в запись
дословно, как только у окружения появляется ключ — а с учётом ветки снятия гейта (см. шапку)
между продовой записью и ПДн клиентов остаётся ровно одна repository variable.
`privateMode` эту дыру закрывает, но забирает
вместе с текстом URL, заголовки страниц и ярлыки кликов — отклонён 2026-09-16 именно поэтому.
Остаётся точечная разметка.

## 2. Механика трекера — сверено с распакованным `@openreplay/tracker@18.0.6`

Всё ниже проверено чтением `node_modules/@openreplay/tracker/dist/lib/index.js`, а не документации.

| Факт в коде пакета | Следствие для плана |
|---|---|
| `DEPRECATED_ATTRS = { htmlmasked: 'hidden', masked: 'obscured' }` | используем только `data-openreplay-obscured` / `data-openreplay-hidden`; старые имена дают warning в консоль |
| `Sanitizer.handleNode`: `if (this.obscured.has(parentID) ‖ hasAttr(node,'obscured')) this.obscured.add(id)` | наследование по поддереву — **основной рабочий инструмент**: атрибут на контейнере закрывает всё внутри |
| `hasOpenreplayAttribute(node, 'unmask')` вызывается **только** внутри ветки `if (this.options.privateMode)` | ⚠️ вне `privateMode` отмены наследования НЕ существует. Стратегия «замаскировать корень и точечно открыть» невозможна — размечаем снизу вверх, от блоков |
| `sanitize(id, data)` → `stringWiper` заменяет каждый непробельный символ на `*` | длина строки и вёрстка сохраняются, экран остаётся узнаваемым |
| `sendImgAttrs`: при `isObscured(id)` → `sendPlaceholder(id, img)` | `<img>` внутри обскуренного блока (сканы, аватары, превью документов) закрыт автоматически |
| `commitNode`: при `isHidden(id)` узел клонируется **без детей**, с проставленными `clientWidth/clientHeight` | `hidden` не ломает сетку — оставляет пустой блок того же размера |
| `getInputValue`: `isObscured(id)` → `InputMode.Obscured`, `isHidden(id)` → `InputMode.Hidden` | поля ввода уже закрыты глобально (`defaultInputMode: 2`), разметка их только усиливает |
| `sendNodeAttribute`: `if (['alt','placeholder'].includes(name) && sanitizer.privateMode) value = value.replaceAll(/./g,'*')` — и **больше ни одной** проверки | 🔴 **вне `privateMode` атрибуты не маскируются вообще**; `alt`/`placeholder` закрыты только в нём. См. §3 |
| `sendNodeAttribute`: `if (name === 'href' ‖ value.length > 1e5) value = ''` | `href` обнуляется всегда — ПДн в query-строке ссылки в запись не идут |
| `commitNode`: цикл `for (attr of el.attributes) sendNodeAttribute(...)` выполняется и для hidden-узла (клон мелкий, атрибуты у него те же) | ⚠️ `hidden` **не спасает** `title`/`alt`: `<iframe title={filename}>` отдаёт имя файла даже скрытым. Атрибуты закрываются только фазой 4 |
| `TopObserver`: захват iframe — `captureIFrames && !hasOpenreplayAttribute(node,'obscured')`, атрибут читается у **самого** узла в node-callback | ⚠️ наследование от обёртки тут не работает: атрибут ставится на сам `<iframe>` |
| `getTargetLabel`: `data-openreplay-label` → label инпута → custom attr → `#id` → **селектор по классам** → `getInnerTextSecure` | ярлык клика почти всегда берётся из классов (Tailwind), до текста дело доходит редко; у obscured-элемента текст всё равно придёт звёздочками. Управляемый ярлык даёт только `data-openreplay-label` |
| опция `domSanitizer(node) => SanitizeLevel` (`0 Plain / 1 Obscured / 2 Hidden`) | централизованная альтернатива атрибутам; всё равно требует признака в DOM — см. §9 «Отклонённые варианты» |

## 3. 🔴 Расхождение с формулировкой задачи: атрибуты не маскируются

`sendNodeAttribute` отправляет значение как есть. Не отправляются вовсе `src`, `srcset`,
`integrity`, `crossorigin`, `autocomplete`, `on*` и `value` у `<input>`; `href` обнуляется.
`alt` и `placeholder` маскируются **только при `privateMode`**, который у нас выключен.
`title` и `aria-label` не маскируются ни при каких настройках. **Наследование `obscured` на
атрибуты не распространяется** — оно применяется к текстовым узлам, картинкам и полям ввода;
`hidden` тоже не помогает: атрибуты отправляются и со скрытого узла.

Мест-кандидатов около сотни (узкая регулярка по `title|alt|aria-label|placeholder` со словарём
из 2.1 даёт 104; всего `title={` в `src/` — 472, поэтому точное число даёт только скрипт из 2.1,
а не цифра в этом абзаце). Подтверждённые примеры:

- `src/pages/Training/components/analytics/InteractionsSubTab.tsx:404` — `title={row.client_full_name ?? undefined}`
- `src/pages/Training/components/analytics/PromisesAndCallbacksSubTab.tsx:461` — то же
- `src/pages/Training/components/analytics/LeaksSubTab.tsx:468` — то же
- `src/pages/ClientManagement/ClientDetailPage.tsx:1616` — `title={linkedContact.fullName}`
- `src/pages/ClientManagement/components/RecommendersTab.tsx:364` — `title={item.fullName}`
- `src/pages/ClientManagement/components/DocumentPreviewModal.tsx:223` — `<iframe title={filename}>`:
  имя файла документа клиента («Иванов_паспорт.pdf») уходит в запись как есть

Эти места **не размечаются, а исправляются** (фаза 4).

### Фаза 1 — инфраструктура (0.5–1 день, 1 PR)

Делается до разметки, чтобы литерал атрибута не повторялся 100+ раз: опечатка в нём — молчаливая
утечка, которую не поймает ни typecheck, ни lint.

- [ ] **1.1** `src/lib/openreplay/pii.tsx` — **расширение `.tsx`, не `.ts`**: файл содержит JSX,
      с `.ts` сборка встанет на первом же импорте.
      - `export const OPENREPLAY_OBSCURED_ATTR = 'data-openreplay-obscured'`;
      - `export const piiProps = { [OPENREPLAY_OBSCURED_ATTR]: '' } as const`; пустая строка даёт
        в DOM `data-openreplay-obscured=""`, и `hasAttribute` его видит.
        🔴 **Spread только на intrinsic-элемент** (`<div>`, `<td>`, `<span>`) **или на компонент,
        у которого прочитано, что rest уходит на DOM-узел.** Компонент, не пробрасывающий `...rest`,
        молча проглотит атрибут: ни typecheck, ни lint, ни тест этого не заметят — это ровно та
        утечка без следов, ради которой заводится константа. Во всех сомнительных случаях — `<Pii>`,
        и каждое такое место покрывается `expectObscured` в тесте того же PR;
      - `export function Pii({ as = 'span', children, ...rest })` — обёртка для случаев, где своего
        контейнера нет. `as` типизировать простым объединением (`'span' | 'div' | 'td' | 'p'`),
        а не полиморфным generic'ом: универсальная типизация `as` съедает больше времени, чем
        экономит, и здесь не нужна.
- [ ] **1.2** `Column<T>.obscured?: boolean` в
      [`src/components/ui/DataTable.tsx`](../src/components/ui/DataTable.tsx) → атрибут на **обоих**
      `<td>` (строки 473 и 491 — обычная ячейка и ячейка раскрытой строки), **не на `<th>`**
      (строка 401: заголовок колонки — не ПДн и обязан остаться читаемым).
      Закрывает 19 файлов декларативно, колонкой, а не ячейкой.
- [ ] **1.3** Тест-хелпер `expectObscured(node)` рядом с существующими — `src/test/`
      (setup там же: `vitest.config.ts` → `setupFiles: ['./src/test/setup.ts']`). Три случая, не один:
      для Element — `node.closest('[data-openreplay-obscured]')`; для текстового узла —
      от `node.parentElement`; для `<iframe>` — `node.hasAttribute('data-openreplay-obscured')`
      на самом узле, потому что наследование на захват iframe не влияет (§2).
- [ ] **1.4** Юнит-тесты на `pii.tsx` и на колонку `DataTable`. Имя файла — `*.test.tsx`:
      `vitest.config.ts` собирает только `src/**/*.{test,spec}.*`, тест в `__tests__/foo.tsx` не запустится.

### Фаза 2 — инвентаризация (1 день, входит в PR фазы 1)

- [ ] **2.1** `scripts/pii-audit.mjs` — обходит `src/**/*.tsx` (без `__tests__` и `*.test.tsx`),
      печатает `path:line identifier` и выдаёт два списка: места рендера ПДн и ПДн в атрибутах
      `title|alt|aria-label|placeholder` (вход для фазы 4).

      **Словарь задан здесь, а не оставлен на усмотрение.** Три правила, применяются к
      JSX-выражениям и member access, **не** к комментариям и строковым литералам:

      | Ключ | Регулярка | Исключения |
      |---|---|---|
      | `PII_NAME` | `[A-Za-z_]*[fF]ull_?[nN]ame\b`, `\b(first\|last\|middle)_?[nN]ame\b`, `\b\w+EmployeeName\b` | — |
      | `PII_ADDR` | `[A-Za-z_]*[aA]ddress\b` | `ip_address`, `ipAddress`, `email_address`, `address_type`, «address bar» |
      | `PII_FREE` | `\.(notes\|comment\|comments\|description)\b` | **advisory, в `--check` не входит** — см. ниже |

      ⚠️ Ведущий `[A-Za-z_]*` вместо `\b` — не украшение: `\bfullName\b` **не матчит**
      `clientFullName`, а `\b(full)?[aA]ddress\b` не матчит `clientAddress`, потому что `\b`
      не ставится между двумя словесными символами. С `\b` словарь пропустил бы ровно те
      производные, ради которых он расширялся.

      🔴 **`PII_FREE` — отдельная секция вывода `free-text candidates`, а не часть `--check`.**
      Без ограничений он даёт ~116 файлов, где большинство — описания шаблонов, курсов и настроек.
      Ограничить его «объект типизирован как `Client`» нельзя двумя способами сразу: таких типов
      **нет** в `src/types/api.ts` (там `User`, `ApiError`, `ApiResponse` и ещё 26 экспортов),
      а `Client` объявлен дважды и в других местах (`features/clients/api/types.ts:208` и
      `pages/ClientManagement/types.ts:7`, это разные интерфейсы), `Payment` — в

      Сигнатура — `__piiAudit(values?: Iterable<string>)`, и аргумент здесь не украшение:
      в тестах API мокается `vi.fn` (msw в зависимостях нет), интерцептор там не сработает,
      поэтому значения подаются явно. Объявление — через `declare global`, подключение —
      `if (import.meta.env.DEV) void import('./piiAudit.dev')` в точке вызова, иначе «ноль веса
      в прод-бандле» не гарантирован.

      Точка подключения — `src/main.tsx:79`, рядом с `requestIdleCallback(() => startOpenReplay())`.
      Интерцептор ставится на **оба** axios-инстанса (`src/lib/api.ts:28` и
      `src/features/credit/api/creditApi.ts:105`): кредитный модуль ходит своим, и половина ответов
      мимо детектора обесценивает его вывод.

      Как работает: axios-интерцептор в дев-режиме собирает из тел ответов значения полей по
      словарю из 2.1 (ФИО, адреса, комментарии) в `Set<string>`; `window.__piiAudit()` обходит
      `document.body` через `TreeWalker` по текстовым узлам плюс атрибуты `title|alt|aria-label`,
      ищет эти значения и печатает таблицей те, у которых **нет** предка с
      `[data-openreplay-obscured]`. Для порталов обход идёт от `document.body`, а не от корня
      приложения, — иначе модалки выпадут из проверки.

      Зачем: превращает «посмотреть запись покадрово» в проверку, которая **называет пропущенный
      узел поимённо**. Глаз на кадре не видит того, что не попало в кадр; детектор видит всё,
      что сейчас в DOM. Это единственный шаг плана, который отвечает на «пропущенный блок —
      утечка» не обещанием, а списком.

## 7. Критерии приёмки

Из задачи:

- На записи реального сценария (клиент → звонок → платёж) ФИО, адреса и тексты комментариев в звёздочках.
- URL, заголовки экранов и навигация остаются читаемыми.
- Портальные модалки проверены отдельно.
- Снят временный гейт в `build.yml`.

Добавлено по итогам разбора пакета и кода:

- ПДн отсутствуют в `title`/`alt`/`aria-label`/`placeholder` — проверено в инспекторе записи,
  а не глазами по кадру (атрибуты трекер не маскирует вообще).
- Есть автоматический барьер, ломающий CI на новом неразмеченном месте рендера ПДн.
- При снятии гейта проверены **оба** пути сборки (`build.yml` и `CD.yml`), а не один.
- `window.__piiAudit()` даёт пустой вывод на всех экранах сценария и на экранах из 6.7 **[HUMAN]**.

## 8. Как ревьюить PR с разметкой

Разметка — это диффы из сотен однотипных строк, в которых ревьюер перестаёт видеть детали к
третьему файлу. Поэтому проверка сводится к четырём вопросам, а не к чтению всего диффа:

1. **Атрибут на контейнере или на поле?** Атрибут на каждом `<span>` внутри карточки —
   не ошибка, но признак того, что автор не нашёл контейнер; при следующем рефакторинге
   новое поле в этой же карточке окажется незакрытым.
2. **Не закрыт ли лишний контекст?** Внутрь `obscured` не должны попадать заголовки экранов,
   названия колонок, пункты навигации, статусы. Если попали — по записи перестанет быть понятно,
   где был оператор, а это `privateMode` окольным путём.
3. **Есть ли в PR тест с `expectObscured`?** Для порталов — обязателен: наследование их не
   достаёт, и это единственное место, где разметка ломается молча.
4. **Прогнан ли `window.__piiAudit()` на затронутых экранах?** Вывод прикладывается к PR.
   Пустой вывод — не доказательство отсутствия ПДн вообще, но доказательство того, что автор
   открыл экран и посмотрел.

Отдельно: PR с разметкой не должен содержать ничего, кроме разметки. Любая правка логики в том же
коммите делает дифф нечитаемым и прячет пропуск.

## 9. Отклонённые варианты

| Вариант | Почему нет |
|---|---|
| `privateMode: true` | Забирает URL, заголовки документов и ярлыки кликов вместе с текстом — по записи не понять, на каком экране был оператор. Отклонён 2026-09-16. |
| «Замаскировать корень приложения, точечно открыть `data-openreplay-unmask`» | В 18.0.6 `unmask` читается **только** внутри ветки `privateMode`. Вне её отмены наследования нет — вариант сводится к предыдущему. |
| `domSanitizer` с эвристикой по форме текста (буквы → маска) | Это `privateMode` окольным путём, плюс вызов функции на каждый узел при каждой мутации DOM — на тяжёлых таблицах это регресс производительности. |
| `domSanitizer` со списком CSS-селекторов вместо атрибутов | Признак в DOM всё равно нужен, а селекторы завязываются на вёрстку и молча перестают совпадать при рефакторинге. Атрибут переживает переезд разметки. |
