# Конфигурация Forgejo-раннеров `fe-prionex`

Санитизированная копия боевой конфигурации compose-проекта
`/opt/forgejo-runner-fe-prionex/` на хосте `s1` (`10.67.0.1`), снятая
2026-08-12 в рамках Story 1.9. До этой story конфигурация раннеров
существовала только на хосте — этот каталог первый раз кладёт её в
репозиторий (см. [D13](../migration-decisions.md#d13)).

## Что здесь лежит

| Файл | Что это |
|---|---|
| `docker-compose.yml` | Весь compose-проект: `dind` + `runner` (Story 1.7, `s1-fe-prionex-1`) и `dind2` + `runner2` (Story 1.9, `s1-fe-prionex-2`) |
| `config.yml` | Конфигурация runner 1 (`forgejo-runner`) |
| `config-2.yml` | Конфигурация runner 2 |
| `.env.example` | Санитизированный шаблон `.env` — реальные значения только на хосте |

## Чем это НЕ является

**Это запись, а не механизм деплоя.** Ничто не применяет эти файлы
автоматически ни к одному хосту. Если конфигурация на `s1` изменится, эта
копия не изменится сама — её нужно обновить вручную в отдельном коммите.
Расхождение между этой копией и боевым хостом возможно и ожидаемо, если
кто-то забудет её обновить.

## Что исключено намеренно

- **`.runner`** — постоянный секрет инстанса раннера (по одному на
  `data/runner/.runner` и `data/runner-2/.runner` на хосте). Не коммитится
  никогда.
- **Токен регистрации** — одноразовый (`GET
  /repos/CRM/fe-prionex/actions/runners/registration-token`), не хранится
  здесь вовсе.
- **`.env`** — заменён на `.env.example` с плейсхолдерами.

## Два нагруженных жёстко закодированных значения

Обе точки задокументированы прямо в файлах, где заданы, но собраны здесь
для быстрого поиска:

1. **`cache.host`** (`config.yml` (найдите `host:` в секции `cache:` — номер строки намеренно не указан) / `config-2.yml`, после добавления
   баннера — см. комментарий рядом со значением) — это **закреплённый IP
   контейнера** в сети `192.168.226.0/24` (`.3` у runner 1, `.4` у runner 2),
   а не адрес хоста. Если проект когда-нибудь перенумеруют, кэш **тихо**
   умирает — отсутствующий cache-сервер не роняет джобу (см. таблицу
   ловушек в Story 1.9, «Trap 3»), поэтому это легко не заметить.
2. **`container.options`** — `--add-host git.crm-prionex.com:10.67.0.1` и
   `DOCKER_HOST=tcp://172.17.0.1:2375`. Без `--add-host` job-контейнер не
   может резолвить registry по имени вообще (split-horizon DNS резолвит его
   публично изнутри вложенного `dind`); без правильного `DOCKER_HOST` job не
   достаёт до `docker build` вложенного движка.

## Раннер 1 vs раннер 2 — что отличается

- **Свой `dind`** у каждого раннера (`dind` / `dind2`), не общий — решение
  и его обоснование записаны в [D13](../migration-decisions.md#d13).
- **Свой `cache.host`** у каждого — общий кэш означал бы, что раннер 2
  теряет кэш при падении раннера 1.
- Метки, образ раннера, `capacity` и `restart` — идентичны.

## Как проверить дрейф (добавлено code review 1.9, 2026-08-12)

До этой правки механическая сверка ничего не давала: копия намеренно отличалась от хоста и
баннером, и `LOAD-BEARING`-комментариями, так что непустой `diff` не отличал «наши пометки» от
настоящего расхождения. Теперь комментарии одинаковы на обеих сторонах, и **единственное
ожидаемое различие — восьмистрочный баннер в начале каждого `config*.yml`**.

```sh
ssh root@10.67.0.1 'cat /opt/forgejo-runner-fe-prionex/config.yml' \
  | diff - docs/runners/config.yml | grep -c '^[<>]'   # ожидается 8
ssh root@10.67.0.1 'cat /opt/forgejo-runner-fe-prionex/config-2.yml' \
  | diff - docs/runners/config-2.yml | grep -c '^[<>]' # ожидается 8
ssh root@10.67.0.1 'cat /opt/forgejo-runner-fe-prionex/docker-compose.yml' \
  | diff - docs/runners/docker-compose.yml | grep -c '^[<>]' # баннер + строка `name:`
```

Больше восьми — конфигурация на хосте изменилась и копию надо обновить вручную. Автоматики нет:
это по-прежнему запись, а не механизм.

## Сверка раннеров между собой (добавлено Story 1.12, 2026-08-13)

Проверка выше сравнивает **каждый файл с хостом** и по построению не видит расхождения
**между раннерами**. Это не теоретический пробел: 13.08 к сети `forgejo_forgejo` был подключён
только первый `dind`, второй остался изолированным и нашёлся отдельной проверкой. Незамеченным
это дало бы падение всех джоб, попавших на раннер 2, при исправно работающем раннере 1 — то есть
перемежающийся отказ без внятной причины, ровно в той паре, которую Story 1.9 строила ради
распределения нагрузки.

**Строка `options` обязана быть побайтово одинаковой у обоих.** Она несёт `--add-host` и для
registry, и для OpenBao; разойдясь, она ломает половину джоб молча.

```sh
diff <(grep '^  options:' docs/runners/config.yml) \
     <(grep '^  options:' docs/runners/config-2.yml) \
  && echo 'options identical — ok' \
  || echo '🔴 DRIFT: раннеры разошлись по container.options'
```

**А эти три значения обязаны различаться** — совпали, значит файл скопировали целиком и раннер 2
работает с чужими адресами:

```sh
for k in '  host:' '  docker_host:'; do
  a=$(grep "^$k" docs/runners/config.yml); b=$(grep "^$k" docs/runners/config-2.yml)
  [ "$a" != "$b" ] && echo "ok: $k различается" || echo "🔴 $k совпал у обоих"
done
```

Ожидаемо: `cache.host` — `.3` против `.4`, `docker_host` — `dind` против `dind2`.

**Правило, а не пожелание:** любое изменение одного раннера применяется и проверяется на обоих в
одном заходе. Проверка на хосте — из джоб-эквивалентного контейнера внутри **каждого** `dind`,
а не с хоста и не из контейнера раннера:

```sh
for d in forgejo-runner-fe-prionex-dind forgejo-runner-fe-prionex-dind-2; do
  ssh root@10.67.0.1 "docker exec $d docker -H tcp://localhost:2375 run --rm \
    --add-host openbao:172.20.0.5 --entrypoint sh curlimages/curl:latest \
    -c 'curl -s -o /dev/null -w \"%{http_code}\n\" --max-time 10 \
        http://openbao:8200/v1/sys/seal-status'"
done   # ожидается 200 на обоих
```
