# Разметка ПДн для OpenReplay: как размечать новое место

Короткий рабочий документ. Полный разбор механики трекера и история решений —
в [`openreplay-pii-markup-plan.md`](openreplay-pii-markup-plan.md); приёмочная таблица
по маршрутам — в [`openreplay-pii-checklist.md`](openreplay-pii-checklist.md).

## Зачем это вообще

Трекер маскирует **цифры** (`obscureTextNumbers`) и значения полей ввода
(`defaultInputMode: 2`). **Буквы не маскирует ничто.** ФИО, адреса и свободные
комментарии операторов попадают в запись дословно, если не разметить блок,
который их рендерит.

## Если CI упал на `pii-audit`

Сообщение называет файл, строку и идентификатор. Дальше — по виду находки.

### `🔴 UNMARKED PII RENDERED AS TEXT`

Разметить **контейнер**, а не поле. Атрибут наследуется вниз по поддереву, поэтому
атрибут на карточке закрывает и то, что в неё доедет при следующем рефакторинге.

```tsx
import { piiProps } from '@/lib/openreplay/pii'

<p className="…" {...piiProps}>{client.fullName}</p>
```

Если своего контейнера нет — обёртка:

```tsx
import { Pii } from '@/lib/openreplay/pii'

<span>
  {t('screen.titlePrefix')} <Pii>{client.fullName}</Pii>
</span>
```

**Подпись поля, заголовок экрана и название колонки остаются снаружи и читаемыми.**
Запись, по которой не понять, где был оператор, — это `privateMode` окольным путём,
отклонённый 2026-09-16 ровно за это.

Для таблиц — флаг на колонке, атрибут сядет на `<td>` и никогда на `<th>`:

```tsx
{ key: 'fullName', header: t('…'), obscured: true, render: (r) => r.fullName }
```

Те же флаги есть у `FieldGrid` (карточка сотрудника), `SearchableSelect` (`obscured`)
и `DataTable` (`expandedObscured` — для строки раскрытия).

### `🔴 PII IN AN ATTRIBUTE THE TRACKER DOES NOT MASK`

🔴 **Разметка здесь не помогает.** Вне `privateMode` трекер отправляет `title`,
`alt`, `aria-label` и `placeholder` дословно — и с обскуренного узла, и со скрытого.
Значение надо **убрать**, а не закрыть.

| Что за элемент | Что делать |
|---|---|
| hover-reveal (видно `#123`, в `title` — ФИО) | `<PiiTooltip label={fullName}>…</PiiTooltip>` — Radix рендерит контент текстовым узлом, а текстовые узлы маскируются |
| иконка или аватар без текста | заменить значение на ключ роли (`common.userAvatar`) |
| `title` буквально дублирует текст рядом | снять атрибут |
| `placeholder` с примером ФИО | заменить на обобщённый |
| значение **не** ПДн (`department`, статус, `ip_address`, i18n-ключ) | **не трогать** — это доступность, а не утечка |

### `🔴 <iframe> STILL CAPTURED`

```tsx
<iframe src={blobUrl} title={t('…')} {...piiProps} />
```

⚠️ Атрибут — **на самом `<iframe>`**, не на обёртке: `TopObserver` читает его в
node-callback, наследование не действует. `captureIFrames` по умолчанию `true`,
поэтому содержимое same-origin фрейма — включая `blob:`, наследующий наш origin —
иначе пишется в запись целиком.

### `🔴 dangerouslySetInnerHTML OUTSIDE ANY MARKED NODE`

Всё, что рендерит этот sink, приходит строкой в рантайме — идентификаторов у текстовых
узлов нет, аудит их не видит **вообще**. Поэтому правило структурное: атрибут на самом
элементе или на предке, наследование закроет всё, что породит HTML.

```tsx
<div dangerouslySetInnerHTML={{ __html: safeHtml }} {...piiProps} />
```

### Отрендеренный текст для клиента — отдельный класс

Письмо, отправленное SMS, разрешённый шаблон (`previewBody`), расшифровка звонка, ответ
ассистента. Ни одно имя поля его не описывает: идентификатор — `previewBody`, `message`,
`utt.text`. Размечается **контейнер**, в котором этот текст лежит; аудит выносит такие
места в advisory-секцию по форме идентификатора и владельцу (`letter.subject`,
`messageData.body`, `previewBody`), но **не в `--check`** — те же слова называют и UI-текст.

### `ℹ️ free-text candidates`

Advisory-секция, в `--check` не входит. Разбирается руками по имени получателя:
`client.notes`, `contact.comment`, `interaction.description` — размечать;
описание шаблона, курса или настройки — не ПДн.

## Порталы

🔴 Наследование **не пересекает портал**. Radix (`Modal`, `DropdownMenu`, `Select`,
`Tooltip`) и `sonner` рендерят под `document.body`, поэтому размеченный триггер не
закрывает содержимое. Атрибут ставится **внутри контента**.

Целиком `<Toaster />`, `Modal`, `Tooltip`, `DropdownMenu` и `Select` не размечаются —
иначе исчезнут системные сообщения и подписи интерфейса. Размечается конкретный вызов.

## Allowlist — только с причиной

`scripts/pii-audit.allowlist.json`, массив `{ path, identifier, reason }`.

Ключ — **путь + идентификатор, никогда не номер строки**: строки сдвигаются, и запись
молча перестаёт совпадать. Скрипт это и проверяет — запись с полем `line` он отвергает,
а о записях, которые ни с чем не совпали, сообщает отдельной секцией: запись,
которая ничего не закрывает, — это дыра, пережившая того, кто её добавил.

Причина пишется словами, а не «false positive». Хорошая причина объясняет, **почему
значение не является ПДн** («портфель — не человек», «рендерится `errors.<field>.message`,
то есть текст интерфейса»).

## Проверить себя до пуша

```bash
npm run pii-audit                       # полный отчёт
npm run pii-audit -- --check            # то же, что в CI
npm run pii-audit -- --check src/pages/Training
npm run test:run                        # включает смоук детектора в jsdom
```

В dev-сборке в браузере:

```js
__piiAudit()                 // значения, пришедшие от API за этот сеанс
__piiAudit(['Иванов Иван'])  // явные значения
```

Детектор обходит `document.body` (то есть видит порталы), ищет эти значения в
текстовых узлах и в атрибутах и печатает таблицей всё, у чего нет предка с
`[data-openreplay-obscured]`. Пустой вывод — не доказательство отсутствия ПДн
вообще: он проверяет **те значения, которые вернул API**, в **том DOM**, который
сейчас на экране.

## Два барьера, и оба нужны

| | что видит | чего не видит |
|---|---|---|
| `scripts/pii-audit.mjs` (CI) | **новый исходник** — ФИО/адрес по словарю, атрибуты, `<iframe>`, HTML-sink | свободный текст (только advisory), значение, у которого нет имени в словаре, рантайм: перенос блока, обёртку, портал |
| `window.__piiAudit()` + смоук в jsdom | **новую вёрстку** — то, что реально в DOM | то, что не отрендерилось |

Ни один не заменяет другой.

## Чего не размечать никогда

URL, заголовки экранов, пункты навигации, названия колонок, статусы, суммы, даты,
метрики, `ip_address`, `email_address` (уже закрыт `obscureTextEmails`), названия
отделов, ролей и должностей, системные сообщения об ошибках.
