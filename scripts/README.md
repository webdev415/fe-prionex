# Инструменты разработки

## `mutation-check.mjs` — мутационная проверка тестов

Зелёный тест не доказывает, что он что-то проверяет: он может быть зелёным по
неверной причине и остаться зелёным, когда причина станет вредной. Скрипт
ломает поведение, которое тест якобы защищает, и смотрит, покраснеет ли тест.

```bash
node scripts/mutation-check.mjs          # все наборы
node scripts/mutation-check.mjs credit   # один набор
```

### Как читать отчёт

| Строка                  | Что это значит                                                                                                                                                 |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ок`                    | Тест действительно защищает поведение.                                                                                                                         |
| `ХХ … тесты ЗЕЛЁНЫЕ`    | **Находка в тесте, а не успех.** Код сломан, проверка промолчала — тест надо переписать. Эту строку легко прочитать как «всё хорошо»; это самая частая ошибка. |
| `?? мутация не внесена` | Текст в исходнике изменился — поправьте описание мутации.                                                                                                      |

Проверяется **набор тестов файла**, а не отдельный `expect`. Если одна проверка
ослабла, а соседняя ловит ту же мутацию, отчёт останется зелёным — и это верно:
поведение по-прежнему защищено.

### Зачем это завели

Три реальных случая из раздела «Кредитный модуль» (29.08.2026) — все прошли бы
в прод незамеченными:

1. Тест «ловит расхождение дохода» был зелёным **без** приведения строки к
   числу: JS сравнивает `'75.26' > 10` сам. Но `'9.50' > '10'`
   лексикографически истинно — то есть на нормальной заявке оператор увидел бы
   ложную тревогу, а тест этого не видел.
2. Тест «локаль не захардкожена» был зелёным при хардкоде `'ru-RU'`:
   приложение схлопывает любую чужую локаль в английскую, и подмена выглядела
   как норма. Ловит только сравнение вывода **двух** языков.
3. Тест разбора анкеты прогонял сломанную ветку через себя каждый прогон и
   оставался зелёным до исправления дефекта и после — просто не проверял
   нужное поле. Дефект жил внутри покрытой фикстуры.

### Как добавить свои мутации

Массив `MUTATIONS` в начале скрипта: файл, точный кусок исходника, замена,
спека и `why` — какое последствие для пользователя наступит, если поведение
сломается. Мутация должна ломать **смысл** (выключать проверку, убирать
приведение, возвращать прежний дефект), а не синтаксис: сломанная сборка красит
тесты и без вашего теста.

Файлы восстанавливаются всегда, включая прерывание по Ctrl+C.
