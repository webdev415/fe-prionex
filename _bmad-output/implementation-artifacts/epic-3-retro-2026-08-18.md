## What went well (and is adopted as practice)

1. **Live guard-outcome matrix** (3.6, adopted by Oleg for Epic 4+). Every branch of a guard is
   proven by a dedicated run — absent (720), equal (721), differ (723), plus a discriminating
   re-run (725) that distinguishes "guard refused" from "guard silently repointed the tag", plus the
   ambiguous fail-closed branch (719). A guard that has never failed proves nothing — three guards
   in this epic could not fire as written and each was found by review, not by its author.
2. **Review the foundation before building on it** (adopted). 3.1 was reviewed before 3.2 was
   written — a direct application of Epic 2's closing lesson (2.1's unreviewed claims were built on
   by three later stories). It paid: the review re-measured the registry, settled two open items
   with one query, and confirmed a falsifiable prediction nobody was scheduled to check.
3. **Probe-first for unproven mechanisms.** 3.4 settled `workflow_call` semantics with 9 probe runs
   before arming anything (finding: `on.workflow_call.secrets` is rejected pre-execution;
   `secrets: inherit` delivers; a caller's `if:` is re-evaluated in the callee where
   `github.event_name` is never `push`). 3.5 proved route (a) and exposed that four documents had
   misdiagnosed the `--add-host` failure — the mechanism was DNS (embedded resolver lost on the
   default bridge), not the route.
4. **A local experiment beats a plausible hypothesis.** 3.6's review patch narrowed an error
   allowlist to `MANIFEST_UNKNOWN` on spec-correct reasoning; one local `buildx imagetools inspect`
   against a missing tag showed the tool emits `: not found` and never surfaces the registry's error
   code. One experiment, zero runs, settled it.

## What hurt (systemic, no blame)

1. **Self-reported run ledgers were low every time, in every story that kept one.**
   3.1: ledger said 0 commits to protected branches, actual 4. 3.4: declared 20 → audit 36 → said
   43 → query-closed at **47**. 3.6: declared 2 → spent 6+. The recorded lesson from 3.4 stands:
   the fix is not "count more carefully" (that was promised and failed again) — it is that a
   self-reported number was the only number without an external check.
2. **Guards that cannot fail, and guards that lie about why they failed.** 3.1's fail-closed
   assertion stopped being fail-closed after the first run; 3.3's keep_pattern guard tested the
   string before the discriminator was appended; 3.5's `__INDEX__` branch never executed once and
   its digest assertion blamed the registry for a tool limitation; 3.6's guard blamed
   `vite.config.ts` for its own `imagetools` index bug. Same class, five stories.
3. **Review fixes introduced regressions of their own.** 3.3: first draft of the newline check
   rejected every value (command substitution strips trailing newlines) — caught before spending a
   run. 3.6: the allowlist narrowing broke the guard's absent path — caught by red run 719. The
   two-pass cycle works but costs a run per iteration when the fix touches matching/parsing.
4. **Permanent side effects from throwaway work.** A probe branch pushed a permanent tag (3.3);
   a probe overwrote the shared `buildcache` (3.6 used this deliberately, but the hazard is the
   same class: a shared mutable tag rewritten by whoever pushed last).

## Key insights

- The epic's core deliverable is not just the pipeline but a **verification vocabulary**: probe
  branches, run budgets, guard matrices, discriminating runs, query-closed ledgers. Epic 4 inherits
  the vocabulary, not only the workflows.
- Error messages are part of the contract: a fail-closed guard that misattributes its own failure
  sends the next reader to the wrong subsystem (measured three times this epic).
- Evidence freshness matters: 3.6 refused to reuse a two-day-old label reading and the retro
  confirms that instinct — the registry state had changed twice in between.
